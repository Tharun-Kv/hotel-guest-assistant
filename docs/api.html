Hotel Guest Assistant
OverviewGitHub ↗
API reference · v1.0

Small endpoints. Clear contracts.

The FastAPI service powers the guest chat, live availability, retrieval inspection, and protected hotel operations workspace.

Base URL: run the backend locally at http://localhost:8000. Responses use JSON and include an X-Request-ID header.

Public endpoints

GET/api/health

Returns service health and application version.

curl http://localhost:8000/api/health
GET/api/hotel

Returns public hotel details, amenities, policies, and room metadata.

curl http://localhost:8000/api/hotel
POST/api/chat

Answers a guest message using identity/FAQ handling, retrieved knowledge, and deterministic availability tools.

message
Required string, up to 1000 characters.
conversation_id
Optional bounded conversation identifier.
conversation
Optional prior user/assistant messages.
curl -X POST http://localhost:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"What time is check-in?"}'
POST/api/availability

Checks the live inventory snapshot for a date range and guest count.

hotel_id
Optional hotel identifier; defaults to default.
check_in/out
ISO dates. Check-in cannot be in the past.
adults
Integer from 1 to the configured guest limit.
curl -X POST http://localhost:8000/api/availability \
  -H "Content-Type: application/json" \
  -d '{"check_in":"2026-10-10","check_out":"2026-10-12","adults":2}'
POST/api/conversation

Creates or replaces a bounded conversation record from validated user and assistant messages.

curl -X POST http://localhost:8000/api/conversation \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"Hello"}]}'
POST/api/knowledge/search

Searches approved hotel chunks without calling an AI provider. Useful for retrieval inspection.

curl -X POST http://localhost:8000/api/knowledge/search \
  -H "Content-Type: application/json" \
  -d '{"query":"breakfast hours","hotel_id":"default","top_k":5}'

Protected operations

Admin routes accept either Basic credentials or the configured X-Admin-Token. Set ADMIN_USERNAME and ADMIN_PASSWORD, or ADMIN_API_TOKEN, in the backend environment.

GET/api/admin/knowledge/documents

Lists indexed source documents. Optional hotel_id filters the result.

curl http://localhost:8000/api/admin/knowledge/documents \
  -H "X-Admin-Token: $ADMIN_API_TOKEN"
POST/api/admin/knowledge/ingest

Scrapes one public URL or indexes approved text. A manual document needs a title.

curl -X POST http://localhost:8000/api/admin/knowledge/ingest \
  -H "X-Admin-Token: $ADMIN_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/amenities","title":"Amenities","hotel_id":"default"}'
DELETE/api/admin/knowledge/documents/{id}

Removes an indexed document and its chunks.

curl -X DELETE http://localhost:8000/api/admin/knowledge/documents/doc_123 \
  -H "X-Admin-Token: $ADMIN_API_TOKEN"
GET/api/admin/inventory

Loads the current room and booking snapshot.

curl "http://localhost:8000/api/admin/inventory?hotel_id=default" \
  -H "X-Admin-Token: $ADMIN_API_TOKEN"
PUT/api/admin/inventory

Atomically replaces rooms, statuses, prices, and booking intervals. The next availability check reads the saved snapshot immediately.

curl -X PUT http://localhost:8000/api/admin/inventory \
  -H "X-Admin-Token: $ADMIN_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"hotel_id":"default","rooms":[{"room_id":"DLX001","status":"available","capacity":2,"price_per_night":260}],"bookings":[]}'

Boundaries worth knowing

Grounded answers

Gemini is optional and server-side. Retrieved hotel chunks are supplied as context, while room availability is decided by the deterministic inventory service.

Credential safety

Never put provider keys in frontend variables. Admin credentials belong in the backend environment and should be sent only over HTTPS outside local development.
