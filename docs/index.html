Product surface

Everything guests ask for.

Every feature is connected to a clear source of truth, with graceful local fallbacks when a model or external page is unavailable.

✦

Grounded chat

Answers are composed from approved hotel information and retrieved source chunks.

⌁

Live inventory

Room status, prices, capacities, and booking intervals are checked deterministically.

◌

RAG ingestion

Operators can scrape a public hotel page or index approved text in the admin workspace.

→

Natural handoff

Clarifying questions guide guests to dates, guest count, and the next useful action.

◷

Human pacing

A calm staged thinking state keeps the assistant transparent while a request is processed.

⌂

Hotel context

Hotel amenities, policies, rooms, and arrival details are available from one assistant.

↗

Responsive UI

A Mobbin-inspired dashboard adapts from a focused mobile chat to a wide desktop workspace.

✓

Safe boundaries

API keys stay server-side and the assistant avoids inventing personal contact details.

Architecture

Three dependable layers.

Requests move through a small set of typed boundaries, making the behavior easy to test and extend.

01 · Guest UI

Next.js + React

Responsive concierge, availability finder, staged response state, and operator console.

02 · API layer

FastAPI services

Validation, chat orchestration, conversations, availability, health, and protected admin routes.

03 · Truth layer

RAG + inventory

Retrieved hotel chunks explain policy; live inventory makes the final room decision.

Quick start

Run the concierge locally.

Configure a server-side provider key when you want model-powered phrasing. The deterministic paths still make the application useful without one.
